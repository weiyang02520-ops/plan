# 专题 1：BDS/GNSS + LiDAR + IMU/轮速多源融合定位

## 研究问题

比赛要求在 BDS 短时中断、LiDAR 几何约束退化并发时保持连续高精度定位。现有机器人已经有轮速 + IMU EKF 和 WTRTK980 NMEA 输入，但没有证据证明 GNSS 已进入 `map -> odom` 融合，也没有 3D LiDAR 融合链路。

## 主流路线和适配判断

| 路线 | 优点 | 代价/限制 | 对本项目的判断 |
|---|---|---|---|
| EKF/ESKF/iEKF | 实时、状态和观测质量易插入 ROS2，适合退化时传播和降权 | 需要正确噪声、时间同步、坐标转换和异常门控 | 首选候选；先做分层融合和质量门控 |
| 因子图/滑窗 | 能把 GNSS 原始观测、IMU 预积分、LiDAR 约束和回环统一处理 | 需要原始观测、外参、优化器、3D 点云和更多算力 | 作为高阶对照，不宜一开始整体迁移 |
| LiDAR-inertial odometry | LiDAR 提供相对几何，IMU 提供高频传播，能应对快速运动 | 主流实现以 3D LiDAR/PointCloud2 为前提 | 当前二维 RPLidar 不能直接套用 |
| 分层定位 | 局部 `odom`、全局 `map`、GNSS 和重定位各自有清晰边界 | 需要管理 `map -> odom` 修正和跳变 | 最接近当前 Nav2 架构 |

## 可靠来源

### F1 — Factor graph fusion of raw GNSS sensing with IMU and lidar for precise robot localization without a base station

- 作者：Jonas Beuchert、Marco Camurri、Maurice Fallon；年份：2023；ICRA 2023，DOI：`10.1109/ICRA48891.2023.10161522`。
- 来源：[Oxford repository](https://ora.ox.ac.uk/objects/uuid%3Aeee434c4-eb81-4539-be89-23587cd66784)、[GitHub code/data](https://github.com/JonasBchrt/raw-gnss-fusion)。状态：`inspected`（论文摘要/机构页 + 仓库说明）。
- 研究问题：GNSS 在无天空视野区域会中断或不稳定，如何与 IMU 和 LiDAR 保持连续轨迹。
- 核心方法/实验：因子图融合原始 GNSS 观测、IMU 和可选 LiDAR；在车辆、四足机器人、森林等低天空可见度环境中验证。
- 关键结果：机构摘要报告全球地球坐标精度约 1–2 m，轨迹连续且平滑；该数字不是 DG-202611 指标结果。
- 可借鉴：原始观测因子、连续性、无基站数据合同和 GNSS/LiDAR 可选集成。
- 不能证明：当前 WTRTK980 NMEA GGA 输出即可支持该方法；也不能证明 20 cm 平面/高程精度。

### F2 — LIO-SAM: Tightly-coupled Lidar Inertial Odometry via Smoothing and Mapping

- 作者：Tixiao Shan、Brendan Englot、Drew Meyers、Wei Wang、Carlo Ratti、Daniela Rus；年份：2020；[arXiv](https://arxiv.org/abs/2007.00258)。状态：`inspected`（论文 HTML 正文）。
- 研究问题：在移动机器人上实时估计 LiDAR-IMU 轨迹并构建一致地图。
- 核心方法/实验：因子图、IMU 预积分、点云去畸变、局部子关键帧和回环因子；在多平台、多环境数据集上测试，也观察 GPS 稀疏/不稳定情形。
- 关键结果：论文报告在激烈运动和多数据集上保持实时/较一致结果；高度方向在无可靠绝对高程时仍可能漂移。
- 可借鉴：因子图如何接收相对/绝对观测，以及“没有可靠高程时不能宣称高程精度”的实验边界。
- 不能证明：当前 2D LaserScan 能直接运行 LIO-SAM；论文不是 BDS 短报文验证。

### F3 — FAST-LIO: A Fast, Robust LiDAR-inertial Odometry Package by Tightly-Coupled Iterated Kalman Filter

- 作者：Wei Xu、Fu Zhang；年份：2020；[arXiv](https://arxiv.org/abs/2010.08196)。状态：`inspected`（论文 HTML 正文）。
- 研究问题：高频、大量 LiDAR 特征和快速运动下如何降低紧耦合滤波计算量。
- 核心方法/实验：紧耦合迭代 EKF、前向/后向传播、点云运动补偿、按状态维度计算 Kalman 增益；在无人机、手持设备和室内外场景测试。
- 关键结果：论文报告室内实验最高约 50 Hz；室外实验平均处理约 7.3 ms/scan，并与 LINS 对比。数字只适用于论文硬件和 3D LiDAR。
- 可借鉴：实时预算、运动补偿、残差/协方差和退化时的状态传播思路。
- 不能证明：Jetson Orin Nano + RPLidar A2 的 2D 实时表现，也不能证明 GNSS 中断期间的全局误差。

### F4 — FAST-LIO2: Fast Direct LiDAR-inertial Odometry

- 作者：Wei Xu、Yixi Cai、Dongjiao He、Jiarong Lin、Fu Zhang；年份：2021；[arXiv](https://arxiv.org/abs/2107.06829)。状态：`inspected`（论文 HTML 正文）。
- 研究问题：避免手工特征提取，直接利用原始点和高效地图结构实现鲁棒 LiDAR-IMU 里程计。
- 核心方法/实验：直接点到地图、iEKF、ikd-Tree 增量地图；在 19 个序列和快速运动平台上评估。
- 关键结果：论文报告某手持实验端到端误差小于 0.06 m，并展示最高约 1198 deg/s 的角速度；这些结果不能迁移为本项目指标。
- 可借鉴：用局部几何质量、邻域平面拟合和计算预算评价 LiDAR 约束。
- 不能证明：没有 3D PointCloud2、点云环信息和外参时无法直接复用；也未解决北斗短报文。

### F5 — MINS: Efficient and Robust Multisensor-Aided Inertial Navigation System

- 作者：Woosik Lee、Patrick Geneva、Chuchu Chen、Guoquan Huang；年份：2025；Journal of Field Robotics，DOI：`10.1002/rob.22546`；[论文](https://doi.org/10.1002/rob.22546)、[代码](https://github.com/rpng/MINS)。状态：`inspected`（期刊摘要 + 仓库 README）。
- 研究问题：在一个滤波式系统中融合 IMU、轮速、相机、LiDAR、GNSS，并处理异步和在线标定。
- 核心方法/实验：高阶流形插值、动态状态克隆、在线内外参/时空标定、仿真和大规模真实数据集。
- 关键结果：摘要报告在定位精度、一致性和计算效率方面优于对比方法，但当前未把具体表格数字抄入本资料库。
- 可借鉴：传感器异步、外参/时间偏移、轮速和 GNSS 质量管理的状态设计。
- 不能证明：代码主要按 ROS1/旧环境组织，GPL-3 许可证和迁移成本必须单独审计，不适合短期直接移植。

### F6 — GLIO: Tightly-Coupled GNSS/LiDAR/IMU Integration for Continuous and Drift-free State Estimation

- 作者：Xikun Liu、Weisong Wen、Li-Ta Hsu；正式出版：2024，IEEE T-IV 9(1):1412–1422，DOI：`10.1109/TIV.2023.3323648`；[机构页](https://research.polyu.edu.hk/en/publications/glio-tightly-coupled-gnsslidarimu-integration-for-continuous-and-/)、[代码](https://github.com/XikunLiu-huskit/GLIO)。状态：`inspected`（论文机构摘要 + README）。
- 研究问题：LIO 有漂移，GNSS 在 NLOS/多路径下有异常，如何连续融合。
- 核心方法/实验：滑窗因子图融合 GNSS 因子、IMU 预积分和 scan-to-map；第二阶段用 scan-to-multiscan 批优化提高全球一致性和 GNSS 异常鲁棒性；UrbanNav 数据集验证。
- 关键结果：机构摘要报告相对传统 GNSS 和独立 LIO 的定位精度改善超过 70%；需注意这是其数据集和基线下的比较。
- 可借鉴：两阶段“局部连续 + 全局一致”结构，以及对 GNSS outlier 的单独处理。
- 不能证明：代码测试环境偏 ROS Melodic、Ceres/GTSAM/3D LiDAR，不能作为现有 ROS2/Humble 系统的直接依赖。

### F7 — Nav2 GPS Localization Tutorial

- 作者/来源：Navigation2 官方文档；版本页面 2026-08 仍可访问；[官方教程](https://docs.nav2.org/tutorials/docs/navigation2_with_gps.html)。状态：`official`、`inspected`。
- 研究问题：如何在 Nav2 中用 `robot_localization` 把 GNSS 转为笛卡尔坐标并提供全局定位。
- 核心方法：局部 EKF 融合轮速+IMU；`navsat_transform_node` 将 GPS 转换为笛卡尔坐标；全局 EKF 融合 GPS、轮速和 IMU；通过 `map -> odom -> base_link` 接入 Nav2。
- 关键结果：这是配置/架构说明，不是性能论文。
- 可借鉴：现有机器人最容易对齐的 TF 分层、双 EKF 和 `navsat_transform` 边界。
- 不能证明：配置示例不代表 WTRTK980、实际场地或 BDS 失锁下满足 20 cm。

### F8 — PRISM-Loc: ROS 2 Humble LiDAR localization stack

- 作者/来源：kjungmo 开源项目；年份：2026 release；[GitHub](https://github.com/kjungmo/prism_loc)。状态：`inspected`（README）。
- 研究问题：如何在 ROS2 中统一 2D MCL、3D NDT-MCL 和 3D LiDAR+IMU+RTK-GNSS 后端，并保持 `map -> odom` 契约。
- 核心方法：2D occupancy-grid MCL、3D NDT-MCL、15 状态 ESKF 融合 3D LiDAR+IMU+RTK-GNSS，带全局候选/初始化入口。
- 关键结果：README 提供可构建、测试和运行命令；当前资料不把其合成数据结果当作实机结果。
- 可借鉴：把不同定位后端统一成 ROS2 `map -> odom`、位姿协方差和 `/initialpose` 接口的系统设计。
- 不能证明：项目较新，不能直接假设已在本机、A2、ZED2i 和 Jetson 上通过；需单独检查许可证、依赖和测试边界。

## 对 DG-202611 的初步结论

- 最适合先验证的是**分层 EKF/质量门控 + 现有 2D Scan-to-Map/AMCL + 主动旋转**，而不是直接移植 GLIO/FAST-LIO2。
- “GNSS 恢复”必须记录恢复前后观测质量、滤波是否重新接纳、`map -> odom` 是否跳变，以及恢复后的轨迹误差。
- “LiDAR 退化”必须有可观测量；至少需要有效特征数量、匹配残差、几何分布/条件数或等价质量指标，不能只写“雷达失效”。
- 现有二维雷达对高程约束不足，是是否需要增加 3D 传感器或其他高程真值源的关键决策点。
